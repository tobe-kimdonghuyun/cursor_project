## 3차 작업 (동일 세션 이후) — build_all_exe.bat 에러 수정

### 문제: 다른 PC에서 push → 이 PC에서 pull 후 build_all_exe.bat 실행 안 됨

#### 에러 증상
```
'-' is not recognized as an internal or external command
'ps2exe' is not recognized as an internal or external command
'to_pipeline.exe"' is not recognized as an internal or external command
))" was unexpected at this time
```

PowerShell 종료 후 cmd.exe가 bat 파일의 PS 섹션을 배치 명령으로 그대로 실행하는 현상.

#### 원인 1: LF-only 줄바꿈

`build_ps1_exe.bat`, `build_standalone_exe.bat` 파일이 **LF-only** 줄바꿈으로 저장됨.
Windows CMD.EXE는 CRLF 줄바꿈을 기대하며, LF-only 파일에서 `exit /b` 이후 PS 섹션을
배치 명령으로 계속 실행하는 버그 발생.

- `git config core.autocrlf = true` 설정 → commit 시 CRLF→LF 변환됨
- 이 PC에서 checkout 시 LF→CRLF로 변환되어야 하지만, Claude Code의 Write 도구가
  LF로 직접 저장하면 autocrlf가 작동하지 않음 (checkout 후에만 변환)

**해결**: `build_ps1_exe.bat`, `build_standalone_exe.bat` → CRLF 변환

#### 원인 2: build_all_exe.bat 라벨-in-블록 버그

```bat
if not "%~1"=="" (
    set "_BUILD_PY=0"
    ...
    :parse             ← if (...) 블록 내부 라벨 불가 (cmd.exe 파싱 오류)
    if "%~1"=="" goto run
    shift & goto parse
)
```

CMD.EXE는 `if (...)` 블록 내부에 라벨을 허용하지 않음.

**해결**: 라벨을 블록 외부로 이동

```bat
if "%~1"=="" goto run
set "_BUILD_PY=0"
...
:parse
if "%~1"=="" goto run
...
shift & goto parse
```

#### 수정 파일

| 파일 | 수정 내용 |
|------|---------|
| `build_ps1_exe.bat` | LF→CRLF 변환 (내용 변경 없음) |
| `build_standalone_exe.bat` | LF→CRLF 변환 (내용 변경 없음, 이미 CRLF였음) |
| `build_all_exe.bat` | 라벨-in-블록 버그 수정 |
